# Изменения NectarLink для Noctalia

Сравнение с исходным [NectarLink](https://github.com/thtbee/nectarlink) `v0.1.6-nightly.10` (локальный тег `original`, `f6b8baf`). Здесь описаны исходники Noctalia-варианта с текущими исправлениями, а не история промежуточных правок. Тег `final-current` (`ded6146`) не содержит более поздних исправлений выбора телефона, тайм-аутов и лимита ID команд, а его установщик ещё указывает на оригинальный репозиторий.

## Локальный API

У оригинала уже был локальный HTTP API: он показывал устройства, читал историю и буфер обмена, отправлял данные и уведомления и открывал камеру или воспроизведение на телефоне. В форке добавлены маршруты для панели Noctalia и уточнено поведение ряда старых команд. Плагин обращается к запущенному NectarLink; с телефоном общается приложение. Сопряжение и разрешения Android остаются обязательными для соответствующих функций.

### Маршруты

| Метод и путь | Отличие от оригинала |
| --- | --- |
| `GET /v1/devices` | К прежним данным устройства, связи и батареи добавлены `ringing` и `controls`: состояние звонка для поиска телефона, значения переключателей и признаки их доступности. |
| `GET /v1/notifications` | Новый список текущих уведомлений с ID телефона-источника. |
| `POST /v1/page` | Новый маршрут чтения сообщений, звонков, фотографий, приложений и плиток Deck. |
| `POST /v1/page-action` | Новый маршрут действий в этих разделах. Чтение страницы не запускает команды. |
| `GET /v1/sessions`, `POST /v1/session` | Новые маршруты чтения, запуска и остановки сессий выбранного телефона. |
| `POST /v1/type` | Новый маршрут отправки текста с ПК на телефон через уже включённую удалённую клавиатуру. |
| `POST /v1/phone-toggle` | Новый маршрут управления телефонными переключателями. |
| `POST /v1/ring` | К запуску звонка для поиска добавлена остановка; ошибки отправки теперь видны клиенту. |
| `POST /v1/camera` | Вместо запасного индекса `0` передаёт точный ID выбранного телефона. |
| `POST /v1/clipboard`, `POST /v1/send`, `POST /v1/notify` | Неверная явно заданная цель отклоняется до изменения буфера ПК или отправки данных. |
| `GET /v1/clipboard`, `GET /v1/timeline`, `POST /v1/play-on-phone` | Прежние маршруты сохранены, обработчики перенесены в отдельные модули. |

### Сервер, доступ и выбор телефона

- В [`local_api.rs`](desktop/app/src/local_api.rs) остались запуск и остановка сервера, применение настроек и таблица маршрутов. HTTP, токен и обработчики разнесены по [`local_api/`](desktop/app/src/local_api/). API по-прежнему привязан к `127.0.0.1` (порт по умолчанию `53320`), а не к сетевому интерфейсу.
- [`http.rs`](desktop/app/src/local_api/http.rs) разбирает запросы, отклоняет `Origin` с `403` и проверяет `Authorization: Bearer …`. Вместо общего пятисекундного лимита теперь есть **5 с на чтение, до 21 с на обработку маршрута и 5 с на запись ответа**. Чтение страницы и её действие имеют собственный лимит в 20 с; это оставляет время вернуть JSON вместо обрыва соединения. Если истекает лимит маршрута, сервер пытается вернуть `504` с `error: "timeout"`.
- [`auth.rs`](desktop/app/src/local_api/auth.rs) сохраняет прежний механизм доступа: порт и токен хранятся в приватном `api-token.json` в профиле приложения. Файл заменяется атомарно; действующий токен сохраняется при смене порта и удаляется при отключении API.
- [`context.rs`](desktop/app/src/local_api/context.rs) принимает известный полный ID либо единственное совпадение по префиксу ID или фрагменту имени там, где маршрут поддерживает такой выбор. Пустая, неизвестная или неоднозначная явная цель **не подменяется другим телефоном**. Без `device` выбирается первый онлайн-телефон, а если таких нет — первый в списке. Новые маршруты страниц и сессий принимают полный строковый ID; формат ID в протоколе телефона не менялся.

<details>
<summary>Запуск сервера, HTTP и хранение токена</summary>

- `init()` применяет загруженные настройки, `sync_from_settings()` заново читает `desktop-settings.json`. `apply_settings()` подставляет стандартный порт вместо нуля в настройках. Если сервер уже работает на этом порту и токен читается, он не перезапускается. Если API выключили, сервер останавливается, а файл токена удаляется. Ошибки подготовки токена и привязки порта попадают в журнал.
- `ServerHandle::stop()` прекращает приём новых соединений сигналом; при освобождении `ServerHandle` вызывается тот же метод. Отдельная функция `stop()` убирает работающий сервер, но сама не удаляет токен.
- `start_on_port()` принимает подключения отдельно друг от друга. При тестовом порте `0` номер назначает ОС. `read_http_request()` извлекает метод, путь, заголовки и тело; для заголовков используется порог 256 КиБ, тело читается по `Content-Length` с ограничением 256 КиБ. `parse_target()` отделяет параметры, `percent_decode()` раскодирует `%XX`, переводит `+` в пробел и сохраняет некорректные `%`-последовательности. Ответ JSON содержит `Cache-Control: no-store`; соединение закрывается. Неизвестная комбинация метода и пути получает `404 not_found`.
- `generate_token()` берёт 32 случайных байта у системного источника и записывает их как 64 шестнадцатеричных символа. Если случайные данные недоступны, токен не создаётся. `read_token_file()` требует ненулевой порт и правильный формат токена, `write_token_file()` записывает данные во временный приватный файл и переименовывает его. Сравнение `constant_time_eq()` не останавливается на первом отличающемся символе. Файл не содержит ключей сопряжения.
- `allowed()` проверяет, что телефон в сети и функция доступна полностью или частично. `visible()` исключает приложения со статусом `Hidden` при работе с чатами из уведомлений. Тестовые `with_state()` и `try_node()` не подключаются к реальному профилю.

</details>

### Страницы, команды, кеш и миниатюры

[`protocol.rs`](desktop/app/src/local_api/protocol.rs) описывает два отдельных запроса: чтение с параметрами списка (`Query`) и действие с `request_id` и подтверждением (`Action`). Неизвестные поля отклоняются. Чтение поддерживает поиск или разбиение на страницы в зависимости от раздела; поле `more` сообщает о продолжении списка.

[`pages.rs`](desktop/app/src/local_api/pages.rs) проверяет границы запроса, направление команды на нужный телефон и доступность функции. `page-action` принимает только предусмотренные действия с `confirm: true`. Сервер выполняет не более одного действия этого маршрута одновременно. Если запрос отклонён как `busy`, новый ID не расходуется. Если действие принято, его ID сохраняется даже при ошибке или тайм-ауте, поскольку команда могла уже уйти. После 10 000 принятых ID новые действия отклоняются с `request_limit_restart_required` до перезапуска приложения.

<details>
<summary>Поля, ограничения и ответы маршрутов страниц</summary>

- **Чтение:** `device` и `page` обязательны; `thread` выбирает переписку, `album` — альбом, `before` и `before_id` задают границу, `offset` и `limit` — смещение и размер страницы, `search` — фильтр, `force` — запрос обновления. Смещение ограничено 5 000, размер — 1–96, `thread` — 1 024 байт, `album`, `before_id` и `search` — 256 байт каждый. `read_inner()` выбирает обработчик раздела; Deck читается без телефона.
- **Действие:** `device`, `action`, `request_id` и `confirm` обязательны. `request_id` содержит 16–128 латинских букв, цифр или дефисов. `id` ограничен 1 024 байтами, `text` — 4 096, `recipients` — десятью получателями. SMS требует непустой текст и получателей, ответ — ID с префиксом `chat:` и непустой текст, набор — номер допустимого формата, остальные действия — ID элемента. Перед исполнением `act_inner()` проверяет возможность на выбранном телефоне, кроме локальных плиток Deck.
- При чтении различаются `invalid_json`, `invalid_page`, `unavailable` и `timeout`. Для действия используются, в частности, `invalid_action`, `duplicate_request`, `busy`, `action_failed_check_phone` и `uncertain_check_phone`. Штатный отказ `pages.rs` возвращает JSON со статусом `409`; внешний лимит HTTP — отдельный `504`. Неудачный ответ не всегда означает, что команда не ушла.

</details>

| Раздел | Что читает и что делает API |
| --- | --- |
| [Сообщения](desktop/app/src/local_api/messages.rs) | Объединяет SMS-ветки и чаты из видимых уведомлений. В чате доступно до 100 последних сохранённых сообщений из уведомлений, а не полная история мессенджера. Отдельно можно отправить SMS или ответить через активное уведомление, если функция разрешена. |
| [Звонки](desktop/app/src/local_api/calls.rs) | Читает историю при наличии разрешения, отдаёт данные активного вызова. Может набрать номер, принять, отклонить или заглушить вызов. Команда для активного вызова требует совпадения его ID, чтобы не сработать на следующем звонке. |
| [Фотографии](desktop/app/src/local_api/photos.rs) | Читает галерею с фильтром по альбому и границей из даты и ID. Дополнительно запрашивает альбомы и миниатюры; их отсутствие не убирает список фотографий. Запрос оригинала возвращает ID передачи, а не сам файл. |
| [Приложения](desktop/app/src/local_api/apps.rs) | Ищет по имени и имени пакета, отдаёт страницы списка и пути к иконкам. Перед открытием заново проверяет точное имя пакета на телефоне. `request_only` означает запрос на открытие, а не готовое окно. |
| [Deck](desktop/app/src/local_api/deck.rs) | Читает до 192 локально настроенных плиток: ID, подпись, страницу и тип действия, без параметров команд. Запускает существующую плитку по ID; произвольную команду через API передать нельзя. |

Для SMS-веток используется граница `before`, а для SMS и истории звонков запрашивается одна дополнительная запись, чтобы выставить `more`: по умолчанию возвращается 5 записей, пределы — 7 и 6 соответственно. Фотографии запрашиваются по 9 для вывода не более 8, альбомы и миниатюры читаются параллельно. В приложениях размер по умолчанию 12, предел 96; поиск не учитывает регистр. Deck читается одним ответом с признаком `complete`, без пагинации. Если SMS недоступны или не загрузились, чаты из видимых уведомлений всё равно могут остаться доступны.

- [`cache.rs`](desktop/app/src/local_api/cache.rs) хранит списки максимум двух телефонов на каждый вид чтения: SMS-ветки — до 20 с, приложения — до 120 с. `force` обходит старый результат. Ошибки, команды и состояние сессий в этот кеш не попадают.
- [`previews.rs`](desktop/app/src/local_api/previews.rs) сохраняет миниатюры и иконки в приватный каталог `noctalia-photo-previews` внутри профиля. Одинаковое содержимое переиспользует файл по хешу. При первом чтении убираются старые файлы этого кеша, а новые порции ограничены по числу и размеру изображений.

Параллельное принудительное чтение может использовать результат, полученный после начала этого запроса. Блокировка кеша удерживается во время загрузки списка, поэтому медленный ответ одного телефона может задержать чтение того же вида для другого. Перед новой порцией миниатюр число отслеживаемых файлов сокращается до 288; следующая порция — максимум 96 изображений по 128 КиБ каждое. Если файл не удалось записать, путь к нему в ответ не попадает.

### Телефон и обмен данными

- [`devices.rs`](desktop/app/src/local_api/devices.rs) сохраняет запуск звонка для поиска без `on` и принимает `on: false` для остановки. Без доступной цели или ядра отвечает `409 no_device`, при ошибке отправки — `502 ring_failed`.
- Там же `phone-toggle` проверяет полный ID, состояние связи и доступность команды на этом телефоне. Управляет режимом звонка, «Не беспокоить», фонариком, Wi‑Fi, Bluetooth и точкой доступа. Для выключения Wi‑Fi нужно отдельное подтверждение, поскольку связь может оборваться.
- [`notifications.rs`](desktop/app/src/local_api/notifications.rs) возвращает до 100 текущих уведомлений от связанных телефонов, исключая приложения, скрытые правилами NectarLink. В ответе есть ID телефона, по которому панель может отфильтровать список. `timeline` по-прежнему читает первую страницу истории отдельно от текущих уведомлений.
- [`clipboard.rs`](desktop/app/src/local_api/clipboard.rs) читает текст ПК и до 20 записей истории. При записи сначала проверяется явно переданный телефон: с `409 no_device` буфер ПК остаётся неизменным. После успешной записи приложение передаёт текст телефону, если есть цель и ядро. Успех подтверждает запись на ПК, а не получение текста телефоном.
- [`transfers.rs`](desktop/app/src/local_api/transfers.rs) оставляет отправку файлов, ссылок и текста одним запросом. Для `send` и `notify` неверный явный адресат отклоняется до отправки. Без `device` действуют прежние сценарии: `send` без выбранного телефона ничего не отправляет, а `notify` может передать выбор получателей ядру. `ok: true` на этих маршрутах не подтверждает доставку.

Для `phone-toggle` режим звонка принимает `mode: ring`, `vibrate` или `silent`, а остальные переключатели — логическое `on`. Фонарику нужны не только разрешения, но и сообщённое телефоном состояние. При успешном включении точки доступа вызывается штатная обработка хотспота. В `timeline` можно передать поиск `q` и `limit` (по умолчанию 20). `notify` требует непустой заголовок и добавляет к нему текст, если он передан. История буфера содержит вид содержимого, превью, источник, направление, время и признак закрепления; без ядра она пуста.

### Сессии, звук, камера и ввод

[`sessions.rs`](desktop/app/src/local_api/sessions.rs) отдаёт состояние и возможность запуска каждой сессии по телефонам. Запрос на изменение передаёт `device`, `kind` и `on`. Для запуска проверяются подключение и поддержка функции. Остановка направляется известному телефону, которому принадлежит сессия, и не требует, чтобы он оставался онлайн.

| Сессия | Назначение |
| --- | --- |
| `pc_audio` | Передача звука с ПК на телефон. Уже активная передача не переключается на другое устройство. |
| `watch` | Воспроизведение текущего видео с ПК на выбранном телефоне. Для запуска нужен подходящий плеер. |
| `phone_audio` | Звук телефона на ПК без открытия окна экрана. |
| `screen` | Окно экрана выбранного телефона на ПК. |
| `webcam` | Режим веб-камеры для выбранного телефона. |
| `keyboard` | Удалённая клавиатура с ПК на телефон; активная сессия другого телефона не переключается. |

`set()` обрабатывает команды сессий по очереди. Если действие затрагивает сессию другого телефона, сервер отвечает `another_device` там, где ресурс общий. `pc_audio` использует штатное действие Deck и тот же путь сохранения настроек. `screen` не запускает второе окно, если уже ожидает разрешения или показывает экран. `phone_audio` и `webcam` учитывают и активную сессию, и ожидание разрешения. Прежний `POST /v1/play-on-phone` использует штатный выбор телефона и выбирает указанный, играющий или первый плеер; `nothing_playing` и `no_phone` различают отсутствие плеера и телефона.

- [`phone_sound.rs`](desktop/app/src/phone_sound.rs) теперь показывает цель и активного звука, и запроса, который ещё ждёт подтверждения. Это не меняет звуковой тракт.
- [`play_on_phone.rs`](desktop/app/src/play_on_phone.rs) и [`play_on_phone/request.rs`](desktop/app/src/play_on_phone/request.rs) отслеживают телефон и этап `preparing` → `asking` → `watching`. Номер запроса не позволяет завершению старой подготовки перезаписать состояние новой. Остановка отменяет локальную подготовку или просмотр; уже отправленное предложение не отзывается на телефоне. [`pc_mirror.rs`](desktop/app/src/pc_mirror.rs) отличает остановку просмотра от закрытия обычной трансляции экрана того же телефона.
- `POST /v1/camera` принимает `photo` или `scan`. [`continuity_camera.rs`](desktop/app/src/continuity_camera.rs) получает точный ID: даже если есть другой онлайн-телефон, он не подставляется. Если цель не найдена, API возвращает `409 no_device`; если выбранное устройство исчезло или ядро недоступно — `409 camera_unavailable`.
- `POST /v1/type` требует уже включённую удалённую клавиатуру для указанного телефона и принимает непустой текст до 16 КиБ. [`mirror.rs`](desktop/app/src/mirror.rs) использует общую очередь ввода, разбивает текст без разрыва символов UTF‑8 и ждёт результата отправки каждой части. При смене телефона или ошибке следующие части не отправляются. Уже поставленный в очередь ввод не отзывается при разрыве HTTP-запроса.

`accepted` для сессии означает принятие запроса, а `transport_only` для ввода — отправку транспортом, не подтверждение со стороны Android. При тайм-ауте действия `uncertain_check_phone` означает, что результат нужно проверить на телефоне или ПК. Сам плагин не повторяет такие команды автоматически.

<details>
<summary>Очередь ввода и состояние «Воспроизвести на телефоне»</summary>

- `input_queue()` запускает общий обработчик при первом обращении. Обычный ввод ставит события в очередь без ожидания. Для ввода по API элемент очереди содержит канал результата. `run_input_queue()` передаёт ошибку ожидающему клиенту, но не останавливает очередь, если этот клиент уже отключился.
- `keyboard_text()` и `keyboard_text_checked()` используют общий `checked_text_chunks()`. `send_checked_text()` сверяет активную цель до старта и перед каждой следующей частью. Уже отправленные части не отменяются при ошибке; ответ не гарантирует, что текст появился на Android.
- `state_for()` показывает состояние только выбранного телефона. `play_for()` проверяет, что он онлайн, а `stop_for()` не прекращает сессию другого телефона. `play_to()` отмечает подготовку и запускает отдельный поток. `Preparing::drop()` очищает только незавершённую подготовку своего запроса.
- `prepare()` собирает плеер, позицию, локальный файл и, когда возможно, адрес вкладки. `execute()` предлагает файл с текущей позиции, ссылку или трансляцию. Если просмотр не поддерживается, но есть запасная ссылка, отправляется ссылка. После сетевого ожидания проверяется, не устарел ли запрос, прежде чем менять состояние и ставить плеер на паузу.
- В `play_on_phone/request.rs` `State::begin()` присваивает номер и запоминает цель, `State::asking()` сохраняет ожидание только для действующего запроса. `State::finish_preparing()` не убирает уже начавшееся ожидание, а `State::observed_watching()` снимает его только для совпадающего телефона. `State::cancel()` меняет номер запроса, делая старую работу неактуальной. Ожидание отображается до 60 секунд; этот таймер не отзывает предложение на телефоне.
- В `pc_mirror.rs` `stop_matching()` проверяет владельца и вид трансляции под одной блокировкой. Для остановки просмотра важно не закрыть обычную трансляцию, которая за это время могла сменить его.

</details>

## Палитра Noctalia

- [`external_palette.cpp`](desktop/app/cpp/external_palette.cpp) читает существующий `noctalia-colors.json` в каталоге конфигурации Qt, обычно `~/.config/nectarlink/`. Он проверяет размер (до 64 КиБ), режим `light` или `dark` и обязательные роли со значениями `#RRGGBB`. Загрузчик следит за файлом и каталогом: учитывает появление, замену или удаление файла без перезапуска приложения. NectarLink не создаёт и не экспортирует палитру.
- [`Theme.qml`](desktop/app/qml/Theme.qml) применяет внешние цвета и режим только к **Hive**. Анимация остаётся штатной; при выключенном переключателе, отсутствии или неверном формате файла используются встроенные цвета. Палитра самого плагина от этого файла не зависит.
- В [`SettingsPage.qml`](desktop/app/qml/pages/SettingsPage.qml) для Hive добавлен переключатель **«Использовать цвета Noctalia»**. [`prefs.rs`](desktop/app/src/bridge/prefs.rs) и [`settings.rs`](desktop/app/src/settings.rs) сохраняют явный выбор как `noctaliaColors`. Старый маркер `noctalia-colors.json.disabled` учитывается только до явного выбора.
- [`build.rs`](desktop/app/build.rs) включает загрузчик и его [заголовок](desktop/app/cpp/external_palette.h) в сборку, а [`app_helpers.cpp`](desktop/app/cpp/app_helpers.cpp) регистрирует его до загрузки QML. Заголовок главного окна в [`MainWindow.qml`](desktop/app/qml/MainWindow.qml) — `NectarLink — Noctalia Integration`; поведение окна этой правкой не изменено.

`PaletteLoader` сразу читает файл, затем сводит уведомления об изменении файла или каталога в одно чтение с задержкой 60 мс. Он передаёт в QML `valid`, `dark` и `colors`. При внешней палитре Hive использует её основной цвет для свечения, а AMOLED не перекрашивает внешние цвета. Без явного выбора настройка следует наличию файла и отсутствию старого маркера; эти проверки не заменяют проверку формата JSON. Сохранённый выбор имеет приоритет, приложение не записывает маркер при чтении.

<details>
<summary>Формат файла палитры</summary>

В корне JSON — `mode` (`light` или `dark`) и объект `colors`. В `colors` нужны следующие поля со строками `#RRGGBB`:

```text
primary, onPrimary, primaryContainer, onPrimaryContainer,
secondaryContainer, onSecondaryContainer,
surface, surfaceContainerLow, surfaceContainer, surfaceContainerHigh,
surfaceContainerHighest, onSurface, onSurfaceVariant, outline,
outlineVariant, warning, error, onError
```

</details>

## Обновления, версия и упаковка

- [`updater.rs`](desktop/app/src/updater.rs) на Linux отключает фоновую проверку оригинального канала, ручную проверку, установку обновления и запуск службы обновлений. Иначе оригинальный пакет мог бы заменить форк и убрать интеграцию. Сборки форка заменяются вручную; профиль находится отдельно.
- [`Cargo.toml`](Cargo.toml) и [`Cargo.lock`](Cargo.lock) используют версию `0.1.5+noctalia.2` для сборки и локальных зависимостей. `v0.1.6-nightly.10` обозначает исходный снимок оригинала, а не номер бинарника.
- [Workflow **Build**](.github/workflows/build.yml) можно запустить вручную без тега и публикации. Такой запуск собирает только Linux на Ubuntu 24.04: `.deb`, `.rpm`, AppImage и архив в артефакт `linux`. Ручной запуск берёт версию исходников; `version` можно передать при вызове из другого workflow. Cargo запускается с `--locked`.
- [Workflow **Release**](.github/workflows/release.yml) для тега `v…+noctalia.…` сверяет его с версией `Cargo.toml`, собирает и проверяет только Linux-пакеты, затем добавляет их, `install.sh` и `SHA256SUMS.txt` в черновик релиза. В именах файлов релиза `+` заменяется на `-`; тег и версия внутри пакетов сохраняются. Публикация такого релиза не обновляет канал автообновлений оригинала.
- [`stage-translations.sh`](desktop/packaging/linux/stage-translations.sh) подготавливает каталоги `.qm` для AppImage, `.deb` и архива. `.rpm` наследует их из `.deb`. Отсутствующие или устаревшие каталоги компилируются из `.ts`; без `nectarlink_ru.qm` упаковка прекращается. Русские подписи переключателя палитры хранятся в `nectarlink_ru.ts`, а не в исходных строках QML.
- [`install.sh`](desktop/packaging/linux/install.sh) ищет релиз, пакет и `SHA256SUMS.txt` только в `vladikchi/nectarlink-noctalia`. Механизм выбора `.deb`, `.rpm` или архива сохранён. Если релиз форка недоступен, установщик не переходит на оригинал. Ссылка на оригинальное приложение для Android остаётся справочной.

Для упаковки переводов скрипт берёт `LRELEASE` либо ищет `lrelease` через `QMAKE` и в `PATH`. Непустые готовые каталоги не пересобираются. AppImage включает Qt, нужные QML-модули и подготовленные видеоадаптеры FFmpeg, но не заменяет системный портал, мультимедийные компоненты и драйверы для захвата. Артефакты ручного workflow доступны со страницы успешного запуска Actions; локальные правки, которых нет на GitHub, туда не попадут.

## Проверки и границы сборки

- Для приложения прошли `cargo check` и 20 тестов локального API. Среди проверок — авторизация и маршруты, неверная явная цель, формат ID, правила подтверждения и отказ от повторного действия. Для палитры есть отдельный [тест загрузчика](desktop/app/tests/external_palette_test.cpp) и тесты сохранения настройки в [`settings.rs`](desktop/app/src/settings.rs).
- Локальный `Nectarlink-0.1.5+noctalia.1-x86_64.AppImage` собран на Arch с Qt 6.12.0 и glibc 2.44. Прошли `--version` и `--ui-check` с временным профилем, русский перевод загрузился. Этот результат относится к локальному пакету, а не к будущему релизу на Ubuntu. Телефон, портал Wayland и другие дистрибутивы этим запуском не проверялись.
- Адреса установщика и отказ при неверной SHA‑256 проверены с подставными ответами GitHub. Установку из публичного релиза это не заменяет.
- Правки Island, раскладки ввода и захвата экрана для Niri вынесены в `nectarlink_niri` и в Noctalia-сборку не входят.
